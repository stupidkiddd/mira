# MIRA 製作計劃

## 目前目標

不要立即製作全部 36 個步驟。第一階段先完成一個可以實際遊玩的開場版本：

1. 無編號的案件及故事簡介
2. 【01/36】輸入姐姐生日密碼 `0916`
3. 【02/36】進入姐姐的舊電腦桌面
4. 【03/36】查看瀏覽紀錄
5. 【04/36】進入 MIRA 舊測試網站
6. 【05/36】恢復姐姐中斷的測試
7. 重新整理頁面後仍保留進度

這段完成後，先測試：

- 玩家是否清楚自己是林以澄，是林以晴的妹妹
- 案件簡介是否足以支持生日密碼謎題
- 登入操作是否自然
- 假桌面是否有調查感
- 玩家是否知道下一步應該按甚麼
- 步驟數字是否在正確時間增加

## 程式檔案結構

不要為 36 個步驟各自建立一個檔案。步驟應由遊戲狀態控制，多個步驟可以共用同一個畫面或程式。

第一階段建議使用以下結構：

```text
mira/
├─ src/
│  ├─ components/
│  │  ├─ IntroScreen.jsx
│  │  ├─ LoginScreen.jsx
│  │  ├─ DesktopScreen.jsx
│  │  ├─ WindowFrame.jsx
│  │  └─ StepCounter.jsx
│  ├─ game/
│  │  ├─ gameState.js
│  │  └─ storyContent.js
│  ├─ styles/
│  │  └─ game.css
│  ├─ App.jsx
│  └─ main.jsx
└─ public/
   └─ images/
```

### 各檔案用途

| 檔案 | 用途 |
|---|---|
| `App.jsx` | 根據遊戲狀態決定顯示簡介、登入、桌面或其他畫面 |
| `IntroScreen.jsx` | 顯示案件資料、故事背景和最後訊息 |
| `LoginScreen.jsx` | 處理 `0916`、錯誤提示和登入成功 |
| `DesktopScreen.jsx` | 顯示假電腦桌面、工作列和圖示 |
| `WindowFrame.jsx` | 所有資料夾及程式共用的視窗外框 |
| `StepCounter.jsx` | 顯示【01/36】等主線進度 |
| `gameState.js` | 記錄目前步驟、已解鎖內容、額外資料和自動保存；不保存玩家已發現的關鍵詞清單 |
| `storyContent.js` | 集中保存案件文字、對話和檔案內容 |
| `game.css` | 管理整個遊戲的視覺設計 |

不建立以下結構：

```text
Step01.jsx
Step02.jsx
Step03.jsx
...
Step36.jsx
```

## 第一階段需要的遊戲狀態

即使試玩版只做到步驟 05，也應先準備：

- 是否已閱讀簡介
- 目前主線步驟
- 已解鎖內容
- 已查看的額外資料
- 已開啟的視窗
- 視窗位置及前後次序
- 玩家在空白記事本自行輸入的原文
- 是否已登入電腦
- 是否已找到 MIRA 網站
- 自動保存時間
- 重新開始遊戲
- 清除進度

每次完成主要目標後，系統才增加主線步驟。重複開啟同一內容不增加步驟。額外資料不改變【目前步驟/36】。

初期可把進度保存在瀏覽器本機，不需要伺服器或玩家帳戶。

## 介面方向

### 電腦介面

使用受舊式 Windows 啟發的虛構系統，不完全複製 Windows。

保留玩家熟悉的概念：

- 桌面圖示
- 工作列
- 開始選單
- 視窗
- 資料夾
- 瀏覽器
- 回收筒

使用自訂顏色、圖示和系統名稱，避免花大量時間追求與真實 Windows 完全一致。

### 主要遊玩裝置

- 電腦瀏覽器優先
- 建議最低畫面寬度約 1024 像素
- 手機可以開啟，但第一版只顯示「建議使用電腦遊玩」
- 完成電腦版核心流程後才考慮重新設計手機操作

### 氣氛變化

- 簡介：冷靜，像案件記錄
- 登入及桌面：普通、稍微陳舊
- MIRA 客服：乾淨而可信的銀行介面
- 發現 E017 後：顏色逐漸減少
- 人為控制測試：完全變成黑白資料畫面

恐怖感來自正常系統被用於不正常的事情，而不是一開始便使用血紅色、閃爍或大量故障效果。

## 圖片製作計劃

圖片需要開始規劃，但暫時不要製作全部最終版本。先使用臨時圖片及簡單圖示驗證操作。

### 開場試玩版需要的圖片

1. 一張普通、稍微陳舊的桌面背景
2. 林以晴的登入帳戶頭像，初期可以使用剪影
3. 文件、相片、瀏覽器、回收筒等桌面圖示
4. 簡介頁的案件版面，不一定需要人物照片

### 必須較早一起設計的關鍵圖片

#### 測試小組團體照

必須包括：

- 林以晴
- 周嘉雯
- 陳國銘
- 玻璃或螢幕反光
- 可以放大看見的 E017 和實驗室 3B 線索

#### 林以晴近照

必須清楚看見：

- 銀色紙鶴耳環
- 其中一邊翅膀的缺口
- 可供後面身份比對的刮痕及耳環扣

#### 公開通報照片

必須與姐姐近照的耳環一致：

- 相同缺口
- 相同刮痕
- 相同耳環扣

三張圖片應使用一致的人物和物件設計，否則比對結果不可信。

不要讓圖片生成工具直接製作 `E017` 等關鍵文字。先生成場景，再由網頁介面或影像工具加入清楚、可控制的文字，避免錯字或模糊字。

## 製作次序

### 第一階段　開場試玩版

1. 整理現有 Vite React 專案結構
2. 建立遊戲狀態和自動保存
3. 製作無編號案件簡介
4. 製作 `0916` 登入畫面
5. 製作假桌面
6. 製作共用視窗外框
7. 製作主線步驟顯示
8. 製作瀏覽器和瀏覽紀錄
9. 製作 MIRA 舊網站首頁
10. 製作恢復中斷測試畫面
11. 測試重新整理後能否恢復進度
12. 讓其他人試玩步驟 01 至 05

### 第二階段　MIRA 與第一個反轉

1. 製作 MIRA 搜尋介面
2. 加入只接受完全相同關鍵詞的搜尋結果
3. 所有需要玩家記下或輸入的關鍵詞使用粗體顯示
4. 製作「救救我」被修改的效果及林以晴項目成員資料
5. 製作 `林以晴` → `E017` → `P17` 的搜尋鏈；文件只在正確搜尋結果中出現
6. 製作不會辨認答案的空白記事本
7. 製作相片放大及檔案資料
8. 製作回收筒和私人訓練例子
9. 完成「MIRA 不是姐姐」的第一個反轉

### 第三階段　E017 與 NOVA

1. 製作測試結果
2. 製作 99.1% 比較
3. 製作家庭影響關係圖
4. 製作內部逐字稿及周嘉雯紀錄
5. 製作要求玩家自行輸入三項線索的網址重建頁
6. 製作被刪除的網頁路徑

### 第四階段　復原與結局

1. 製作復原工具
2. 製作證據核對區
3. 製作公開通報及耳環比對
4. 製作七日時間線
5. 製作撤回頁
6. 製作兩個結局
7. 完成音效、轉場、提示及整體測試

## 第一個完成標準

第一個可交付版本應讓玩家能完整完成：

> 閱讀案件簡介 → 輸入 0916 → 進入桌面 → 打開瀏覽器 → 查看瀏覽紀錄 → 找到 MIRA 舊網站 → 恢復姐姐中斷的測試

達到以上結果，而且重新整理頁面後不會失去進度，才開始大量製作正式照片和後續故事內容。

## 靜態網站注意事項

目前專案使用 GitHub Pages，所有遊戲程式和故事資料都會下載到玩家的瀏覽器。熟悉開發工具的玩家有可能直接查看答案及未解鎖內容。

第一版可以接受這項限制，重點是完成遊戲。如果日後需要真正隱藏答案或未公開章節，才考慮加入伺服器；不要在原型階段增加這項複雜度。
